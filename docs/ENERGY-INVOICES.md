# Energy invoices: import of ZUGFeRD / Factur-X and XRechnung

Decisions (2026-11-11): invoice objects + time series per medium; medium detected and confirmed in a dialog;
duplicates (same supplier + invoice number) skipped and reported; parsing with Mustangproject (Apache 2.0) in the
web service (Java 25) because Mustang 2.x needs Java 11+; the Control Center (Java 8) only shows the dialog and
uploads. The web app can use the same endpoints later.

## Classes (var/classes/AccountingPlugin, translations in var/i18n/AccountingPlugin)

- **Energy Invoices Directory** (exists): new attribute `Medium` (String: `ELECTRICITY`, `GAS`,
  `DISTRICT_HEATING`, `OTHER`; empty for the top folder). The import creates one sub-folder per medium below the
  chosen folder (name de "Strom" / "Gas" / "Fernwärme" / "Sonstiges", local names en/de) and finds it again by
  `Medium`, not by name (if the chosen folder itself has this `Medium`, it is used directly).
- **Energy Invoice** (new, parent: Energy Invoices Directory):
  `Invoice File` (File, original PDF/XML), `Format` (String, e.g. "ZUGFeRD 2.3 EN16931", "XRechnung 3.0 UBL"),
  `Invoice Number`, `Invoice Date` (Date), `Seller`, `Seller VAT ID`, `Buyer` (String),
  `Period Start`, `Period End` (Date), `Medium` (String), `Meter Point` (String: Zählpunkt / MaLo / MeLo if found),
  `Consumption` (Double, number with unit: kWh or m³), `Net Amount`, `Tax Amount`, `Gross Amount` (Double, unit
  currency), `Currency` (String), `Line Items` (String, JSON array: description, quantity, unit, unit price, net,
  tax rate, period).
  All value samples at the period start (else invoice date), note = invoice number.
- **Energy Invoice Data** (new, inherits `Data` like "Base Data", parent: Energy Invoices Directory): the time series
  of a medium folder, created on first import:
  "Verbrauch laut Rechnung" (Value unit = consumption unit), "Kosten netto laut Rechnung", "Kosten brutto laut
  Rechnung" (Value unit = currency). Attribute `Series` (String: `CONSUMPTION`, `NET`, `GROSS`) to find them.
  Sample per invoice: timestamp = period start, value = total of the period, note = invoice number(s). If a sample
  at that timestamp exists (another invoice, e.g. another meter point), the values are added and the invoice
  numbers appended to the note.

## Web service (JEWebService, Mustang only here)

- `POST /JEWebService/v1/invoices/parse?directory={id}` (multipart `file`): parse without storing →
  `{ format, number, date, seller, sellerVatId, buyer, periodStart, periodEnd, currency, net, tax, gross,
  consumption: {value, unit}, meterPoint, items: [...], medium: guess, mediumReasons: [...], duplicate: id|null,
  warnings: [...] }`; 400 with a message if the file is no ZUGFeRD/Factur-X/XRechnung.
- `POST /JEWebService/v1/invoices/import?directory={id}&medium=GAS` (multipart `file`): parse again, check
  duplicate (409 with the existing id), create the medium folder / series objects if missing, the invoice object with
  all attributes and the file, add the series samples. Needs create right on the folder (and write on existing
  series); 403 otherwise. Answer: `{ invoiceId, folderId, series: {CONSUMPTION: id, NET: id, GROSS: id}, warnings }`.
  If a step fails, the objects created by this import are deleted again and the series samples it changed are
  restored (no half-imported invoices).
- Credit notes (type code 381, UBL CreditNote): net, tax, gross and consumption are stored as negative values, so
  they reduce the series; the line items stay as in the document.
- Consumption = sum of line quantities with energy units (KWH, MWH → ×1000 kWh, MTQ = m³; kWh preferred when both),
  fixed fees (MON, DAY, C62, …) not counted. Energy invoices name the same consumption several times (energy
  price, maybe split into HT/NT, grid fee, taxes): the energy lines of one period are split into the largest number
  of groups with equal sums and one group is counted (warning "… name the same consumption n times").
  Medium guess from units (m³ → gas), texts of lines/notes (Strom/Elektr*/Wirkarbeit → electricity; Gas/Erdgas →
  gas; Fernwärme/Wärme → district heating) and seller name; unknown → `OTHER` with a warning.
- Tests with invoices generated by Mustang itself in the tests (neutral names, no real invoices).

### Answers in detail

`POST /invoices/parse` (200):

```json
{
  "fileName": "invoice.pdf", "format": "ZUGFeRD 2.3 EN16931",
  "number": "R-1001", "date": "2026-10-05", "seller": "Supplier A", "sellerVatId": "DE000000000", "buyer": "Customer B",
  "periodStart": "2026-09-01", "periodEnd": "2026-09-30", "currency": "EUR",
  "net": 1234.56, "tax": 234.57, "gross": 1469.13,
  "consumption": { "value": 4321.0, "unit": "kWh" },
  "meterPoint": "DE0000000000000000000000000000001",
  "medium": "ELECTRICITY", "mediumReasons": ["unit kWh", "line text 'Strom'"],
  "items": [ { "description": "Arbeitspreis", "quantity": 4321.0, "unit": "kWh", "unitPrice": 0.25, "net": 1080.25,
               "taxRate": 19.0, "periodStart": null, "periodEnd": null } ],
  "duplicate": null, "warnings": []
}
```

- Dates `yyyy-MM-dd`; amounts as numbers; `consumption` `null` if no energy line; `unit` normalised to `kWh` or `m³`.
- `duplicate`: id of an existing Energy Invoice below `directory` (recursively) with the same seller (VAT ID, else
  name) and invoice number, else `null` (only if `directory` is given and readable).
- Errors: 400 `{ "error": "NOT_AN_E_INVOICE" | "UNREADABLE", "message": "…" }`, 413 if the file is larger than
  20 MB, 401 without login.

`POST /invoices/import?directory={id}&medium=GAS` (201): `{ "invoiceId", "folderId", "series": { "CONSUMPTION",
"NET", "GROSS" }, "warnings": [...] }` (warning e.g. if the consumption unit differs from the existing series, then
the consumption is not added to it); 409 `{ "error": "DUPLICATE", "existing": id }`; 403 without create right on
the folder (or write right on an existing series); 400 for a wrong `medium` or a directory that is no Energy Invoices Directory.
- Error bodies: `{ "error", "message" }` with `error` = `NOT_AN_E_INVOICE`, `UNREADABLE`, `NO_FILE` (400),
  `INVALID_MEDIUM`, `INVALID_DIRECTORY` (400), `FORBIDDEN` (403), `DUPLICATE` (409, plus `existing`), `TOO_LARGE`
  (413).
- Authentication: the Control Center's session (Bearer token or legacy Basic) like all other endpoints.

## Control Center (AccountingPlugin)

- Button "Rechnungen importieren" (where Energy Invoices Directories are shown; folder chooser if several).
- File chooser (multiple, *.pdf, *.xml) → parse each via JEAPI-WS (`JEVisDataSourceWS.parseInvoice`) → dialog table:
  file, format, number, date, seller, period, consumption + unit, net, gross, medium (ComboBox, preselected),
  status (new / duplicate / error with message) → "Importieren" imports the new ones → summary.
- Strings via I18n keys (added centrally).
