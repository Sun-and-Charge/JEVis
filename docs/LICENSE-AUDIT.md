# License audit

Status: 2026-11-05. JEVis is licensed under the GNU GPL version 3 only (see `LICENSE` and `NOTICE`).
This document lists what was checked and the issues that still need a decision or manual work.

## Open issues

1. **Eclipse Milo (OPC UA) is EPL 2.0 only.** `org.eclipse.milo:sdk-client`, `sdk-core`, `stack-client`,
   `stack-core` 0.6.16 are licensed under EPL 2.0 without the "Secondary License" (GPL) designation
   (checked in the license file and the source headers, also on the current main branch), so they are not
   compatible with the GPL. Milo is used by `DataCollector/OPCUA-Driver`, `DataCollector/loytec-xml-dl` and
   the OPC UA browser of the Control Center.
   No GPL-compatible Java OPC UA stack covers what JEVis needs (above all HistoryRead raw and processed):
   Apache PLC4X has no HistoryRead and needs Java 21, the OPC Foundation Java stack is GPL-2.0-only.
   **Decided 2026-11-05:** replace Milo by a separate program `opcua-bridge` written in Go on gopcua (MIT),
   which JEVis calls as a process (JSON over stdin/stdout). Planned after web phase W1.
2. **GPLv3 only** (deferred). The original Envidatec headers say "in version 3", not "or later". Moving to
   a later GPL version would need the consent of the copyright holders.

## Done

- Root `LICENSE` (GPLv3 text), new root `NOTICE` (fork notice, copyright holders).
- `pom.xml`: `<licenses>`, `<organization>`, `<scm>` and project URL point to this repository.
- Source headers:
    - Existing `Copyright (C) ... Envidatec GmbH` notices are **kept unchanged** (GPLv3 §4/§5).
      Only the sentence pointing to openjevis.org was replaced by the URL of this repository.
    - Files changed since 2026-10-01 have an additional line
      `Copyright (C) 2026 Sun and Charge Germany GmbH`.
    - About 1,170 Java files without a license header got a GPLv3 header (`Copyright (C) JEVis contributors`),
      replacing the NetBeans placeholder comments.
- The Control Center shows all licenses under **Help > Licenses**:
    - Maven dependencies, generated by the license-maven-plugin on every build (`JEVisControlCenter/src/license/`)
    - bundled resources, from `JEVisControlCenter/src/main/resources/jevis-licenses/bundled-assets.tsv`
- Links and defaults that pointed to openjevis.org were changed or removed (default host is now
  `localhost`). The Envidatec imprint and privacy pages in `var/templates/www` were removed.
- **Branding:** the login screen, window icon and About dialog use the Sun and Charge images
  `icons/suc_login_banner.png`, `icons/suc_logo.png` and `icons/suc_icon.png`.
- **ISO 50001 standard text:** the old ISO 50001 module (FreeMarker web pages in JEWebService, "ISO 50001"
  plugin in the Control Center, `var/classes/ISO50001Plugin`, `var/i18n/ISO50001Plugin`, `var/freemarker`)
  was removed together with the bundled jQuery, jQuery UI, Chart.js and Font Awesome files and the
  zlib-licensed `NaturalOrderComparator` it used. Its classes contained verbatim clause text of
  DIN EN ISO 50001; they were also taken out of `V3__Create_Base_Classes.sql`, and migration
  `V16__Remove_ISO50001_Classes.sql` removes them from existing databases (run `flyway:repair` once because
  of the changed V3 checksum, see README).
- **"CERN, All Rights Reserved":** `DataPointNoteDialog.java` and `DataPointTableViewPointer.java` are based on
  `de.gsi.chart.plugins.DataPointTooltip` of chartfx 8.1.5, whose pom declares Apache 2.0. The header now
  carries the license grant and a note on the JEVis modifications.
- **Decompiled sources:** the 14 files in `JECommons/.../datatype/scheduler/**` and
  `JECommons/.../json/JsonScheduler*.java` were decompiled from JEVis' own code; they carry the normal GPLv3
  header now.
- **Icons without a source:** the 116 unrecorded icons in `JEVisControlCenter/src/main/resources/icons`
  (PNG/GIF in the folder root, `widget/`, `svg/Snap_to_Grid4.svg`, old JEVis logos) were removed, and an
  Icons8 Excel logo in the Material subset was replaced. Each icon that was still referenced was replaced by
  a Material icon from `google/material-design-icons` (Apache 2.0): SVGs in `icons/MaterialDesignSVG/outlined`
  and, where the code needs a `javafx.scene.image.Image`, the official PNGs in `icons/MaterialDesignPNG/outlined`.
  The language flags in `icons/flags2` are Twemoji 15.1.0 flags (graphics CC BY 4.0). All files are
  unmodified and listed in `bundled-assets.tsv`; paths are constants in `org.jevis.jeconfig.Icon`.
- **iText 5 (AGPLv3):** replaced by OpenPDF 1.3.43 (LGPL 2.1 / MPL 2.0, last version for Java 8) in the
  Control Center (chart and dashboard PDF export, meter labels) and JEReport (PDF splitting). The QR codes of
  the meter labels are drawn from a ZXing matrix, since OpenPDF has no QR code support.
- **`org.json:json`:** updated from 20210307 (JSON License, "shall be used for Good, not Evil") to 20260814
  (public domain).
- **`javax.activation:activation` 1.1 (CDDL 1.0 only):** excluded from `com.sun.mail:javax.mail`, replaced by
  `com.sun.activation:jakarta.activation` 1.2.2 (EDL 1.0). The JAXB annotation API of JECommons is
  `jakarta.xml.bind:jakarta.xml.bind-api` 2.3.3 (EDL 1.0).
- **Code taken from the web:** `tool/DragResizeMod.java` (from a GitHub repository without any license) and
  `plugin/charts/TableViewContextMenuHelper.java` (StackOverflow answer under CC BY-SA 3.0, not compatible
  with GPLv3) were removed. Their functions were rewritten independently from a behaviour description,
  without access to the old code or its sources: moving and resizing of dashboard widgets
  (`plugin/dashboard/WidgetMoveResizeSupport`, `WidgetFrame`, `WidgetHandle`, with unit tests) and the
  column menu of tables (`application/table/TableColumnMenu`).
- **Credentials in example configs:** `Notifier/JENotifier/JENotifierConfig.xml` and `JENotifierConfig2.xml`
  use placeholders. Also removed: an unused method with the login of another server in a comment
  (`Configuration.getDefaultServer`), an obsolete NetBeans action file and four `*.java1~` backup files.
  The old passwords are still in the git history; change them if those servers are still in use.

- **Web app (`JEWebApp`):** GPL-3.0-only. The bundled npm packages (Vue, vue-router, Pinia, vue-i18n and
  their parts) are MIT; `npm run build` writes their license texts and the Montserrat font license (OFL 1.1) to
  `dist/THIRD-PARTY-LICENSES.txt`. Dependencies are installed with `--before` (at least two weeks old) and
  pinned in `package-lock.json`.

### Dependencies checked and compatible

The generated license list (Help > Licenses) also contains these licenses, which are compatible:

- **CDDL / GPL 2.0 with Classpath Exception** (dual license), e.g. `com.sun.mail:javax.mail`, JAXB
  (`jaxb-api`, `jaxb-runtime`, `txw2`, `istack-commons-runtime`, `stax-ex`, pulled in by Milo),
  `javax.activation-api`: used under the GPL 2.0 + Classpath Exception, which allows linking with
  independent modules under any license.
- **EPL 2.0 / GPL 2.0 with Classpath Exception** (dual license): `jakarta.annotation-api`,
  `jakarta.transaction-api`, same reasoning.
- **LGPL** (`openpdf` 2.1, `j-text-utils` 2.0) and **MPL 2.0**: compatible with GPLv3.

## Keeping the license information up to date

- New Maven dependencies appear in the license dialog automatically. If a dependency declares no
  license in its pom, add it to `JEVisControlCenter/src/license/THIRD-PARTY.properties`.
- New icons, fonts or copied code: add a line to `bundled-assets.tsv` and keep the original license notice.
- New source files: use the header from `JECommons/licenseheader.txt`.
