# License audit

Status: 2026-10-28. JEVis is licensed under the GNU GPL version 3 only (see `LICENSE` and `NOTICE`).
This document lists what was checked and the issues that still need a decision or manual work.

## Done

- Root `LICENSE` (GPLv3 text), new root `NOTICE` (fork notice, copyright holders).
- `pom.xml`: `<licenses>`, `<organization>`, `<scm>` and project URL point to this repository.
- Source headers:
    - Existing `Copyright (C) ... Envidatec GmbH` notices are **kept unchanged** (GPLv3 §4/§5).
      Only the sentence pointing to openjevis.org was replaced by the URL of this repository.
    - Files changed since 2026-10-01 have an additional line
      `Copyright (C) 2026 Sun and Charge Germany GmbH`.
    - About 1,170 Java files without a license header got a GPLv3 header (`Copyright (C) JEVis contributors`), replacing
      the NetBeans placeholder comments.
    - Third-party and decompiled files (see below) were left untouched.
- The Control Center shows all licenses under **Help > Licenses**:
    - Maven dependencies, generated by the license-maven-plugin on every build (`JEVisControlCenter/src/license/`)
    - bundled resources, from `JEVisControlCenter/src/main/resources/jevis-licenses/bundled-assets.tsv`
- Links and defaults that pointed to openjevis.org were changed or removed (default host is now
  `localhost`). The Envidatec imprint and privacy pages in `var/templates/www` were removed.

## Open issues

### Dependencies with GPL-incompatible licenses

The generated license list (Help > Licenses) shows dependencies whose licenses the FSF classifies as
incompatible with the GPL. Because the Control Center is distributed as one jar with all dependencies,
these should be resolved:

| Dependency                                                                     | License                                           | Comes from                                 | Suggested fix                                                                                                                                                                          |
|--------------------------------------------------------------------------------|---------------------------------------------------|--------------------------------------------|----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| `org.eclipse.milo:sdk-client`, `sdk-core`, `stack-client`, `stack-core` 0.6.16 | EPL 2.0 (no GPL secondary license)                | Control Center (OPC UA)                    | Ask the Milo project / check whether a version with a "Secondary License" (GPL) designation exists; otherwise move OPC UA into a separate program or use a GPL-compatible OPC UA stack |
| `org.json:json` 20210307                                                       | JSON License ("shall be used for Good, not Evil") | JECommons                                  | Update to `20231013` or newer (public domain since then)                                                                                                                               |
| `javax.activation:activation` 1.1                                              | CDDL 1.0                                          | `com.sun.mail:javax.mail` via OPCUA-Driver | Exclude it and use `com.sun.activation:jakarta.activation` (EDL 1.0 / BSD)                                                                                                             |

`com.itextpdf:itextpdf` (AGPLv3) is compatible, see item 5 below.

### Other issues

1. **ISO 50001 standard text.** `var/classes/ISO50001Plugin`, `var/i18n/ISO50001Plugin` and
   `mysqldb/src/main/resources/db/migration/V3__Create_Base_Classes.sql` contain what appears to be
   verbatim clause text of DIN EN ISO 50001. ISO/DIN hold the copyright, so this text cannot be
   distributed under the GPL. Replace it with your own wording or with clause numbers and titles only.
2. **"CERN, All Rights Reserved".**
   `JEVisControlCenter/.../Chart/ChartPluginElements/DataPointNoteDialog.java` and
   `DataPointTableViewPointer.java` carry only this line and no license grant. They probably come from
   chartfx (Apache 2.0 in the version used here, 8.1.5) or its predecessor extjfx. Confirm the origin and add the
   correct license header, or rewrite them.
3. **Decompiled sources.** 14 files in `JECommons/.../datatype/scheduler/**` and
   `JECommons/.../json/JsonScheduler*.java` say "recreated from a .class file by IntelliJ IDEA".
   If they were decompiled from Envidatec's own code they are GPL; otherwise their origin must be clarified.
4. **Icons without a source.** About 205 PNG/GIF icons in `JEVisControlCenter/src/main/resources/icons`
   (for example `if_*`, `iconfinder_*`, timestamped names, `flags2/`, `svg/grid-svgrepo-com.svg`) have
   no recorded source or license. Iconfinder and SVGRepo icons can be CC BY (attribution needed) or
   non-commercial. Check them and add them to `bundled-assets.tsv`, or replace them with icons from
   the sets already included (Font Awesome, Material Icons).
5. **iText 5 (AGPLv3).** `com.itextpdf:itextpdf` (Control Center, JEReport) is AGPLv3. It is
   compatible with GPLv3, but AGPL §13 applies when the software is offered to users over a network.
   Consider OpenPDF (LGPL/MPL) as a replacement.
6. **GPLv3 only.** The original Envidatec headers say "in version 3", not "or later". Moving to a
   later GPL version would need the consent of the copyright holders.
7. **Code taken from the web.** `JEVisControlCenter/.../tool/DragResizeMod.java` (based on
   github.com/varren/JavaFX-Resizable-Draggable-Node) and
   `JEVisControlCenter/.../plugin/charts/TableViewContextMenuHelper.java` (StackOverflow, CC BY-SA):
   check the licenses and add attribution.
8. **Branding.** Done: the login screen, window icon and About dialog use the Sun and Charge
   images `icons/suc_login_banner.png`, `icons/suc_logo.png` and `icons/suc_icon.png`.
9. **Credentials in example configs.** `Notifier/JENotifier/JENotifierConfig.xml` contains database and
   user passwords of an old server. Replace them with placeholders, and change the passwords if that
   server is still in use (they are in the git history).

## Keeping the license information up to date

- New Maven dependencies appear in the license dialog automatically. If a dependency declares no
  license in its pom, add it to `JEVisControlCenter/src/license/THIRD-PARTY.properties`.
- New icons, fonts or copied code: add a line to `bundled-assets.tsv` and keep the original license notice.
- New source files: use the header from `JECommons/licenseheader.txt`.
