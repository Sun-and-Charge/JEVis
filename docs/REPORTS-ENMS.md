# EnPI report and energy management report (JEReport)

User decisions (2026-11-18): both reports as JEReport templates (XLSX/PDF, sent like every periodic report), the EnPI
report monthly, the energy management report yearly as the basis of the management review (ISO 50001); the energy
management report contains consumption and costs, EnPIs and baselines, actions and nonconformities.

The demo organisation had both report objects (`EnPI-Bericht - Werk`, `Energiemanagement Bericht`) with their report
links, but their templates were removed with the demo import (third-party branding). The new templates are generated,
brand-neutral and fit these links; customers copy the report objects and change the links.

## Templates (`var/report-templates`)

Generated by `JEReport/src/test/java/org/jevis/report3/templates/ReportTemplates.java` (run its `main` with the target
directory after a change and commit both files); `ReportTemplatesTest` fills them with sample data through
`TemplateTransformator` and checks the computed cells (changes, means across sheets, regression, sums).

- **`EnPI-Bericht.xlsx`** (schedule `MONTHLY`)
  - sheet *EnPI*: per EnPI the report month, the previous month, the change and the mean of the last 12 months;
    consumption of the month against the previous month.
  - sheet *Verlauf*: the last 12 months per EnPI with the mean.
  - sheet *Baseline*: linear regression of `Strom Produktion` on `Produktionsmenge` over the last 12 months (slope,
    base load, R² = CORREL²), the model value per month, the expected consumption of the report month and the
    deviation (absolute and %).
- **`Energiemanagementbericht.xlsx`** (schedule `YEARLY`)
  - sheet *Übersicht*: consumption, costs and EnPIs of the year against the previous year; actions and
    nonconformities as numbers.
  - sheets *Verbrauch*, *Kosten*: the months of the year (and of the previous year) with sums/means.
  - sheets *Maßnahmen*, *Abweichungen*: the lists of the energy management link.

### Cover sheet and page footer

Both templates start with a sheet *Deckblatt*: title, the facts of the report (variable `report`, see below), the
table of contents and an approval block (name, function, date, signature) for the management review. Every sheet
has a page footer with the sheet name and "Seite n von m". Month labels use the format `[$-407]MMMM yyyy`, so
LibreOffice on the server prints German month names whatever its own language is. The sheet subtitles add
" – <site>" only when the report has a site.

### Report facts (`report`)

JEReport (`ContextBuilder`, `ReportInfo`) puts the variable `report` into every report (a report link with the same
variable name wins): `name` (report object), `site` (nearest Building above the report, empty without one),
`organisation` (nearest Organization), `periodStart`, `periodEnd` (`dd.MM.yyyy`, end = last day of the current
period), `period` (German text by schedule: "Oktober 2026", "2026", "4. Quartal 2026", "KW 47 2026", a day or a
range) and `createdAt` (`dd.MM.yyyy HH:mm`). Deploy JEReport with `ReportInfo` before uploading templates that use `report`.

### Charts

The overview sheets carry charts in the Sun and Charge colours (Blueberry `#1a2a45`, Sun `#ffde00`, grey for the
previous year), on their own page: EnPI report – EnPI Strom/Gas gesamt over 12 months (line) and the baseline
(measured values as points, the model as line); energy management report – electricity and gas per month against
the previous year and the energy costs per month (columns). JXLS does not move chart ranges, so the series refer to
the rows after the expansion of the 12 months (the overview rows themselves do not move). The month labels come from
hidden helper columns (`MONTH`/`YEAR`, not `TEXT`, which LibreOffice recalculates with the format codes of its
language); the charts show hidden cells. JEReport needs the full OOXML schemas (`poi-ooxml-full` instead of
`poi-ooxml-lite`) to read such charts.

### Template variables (report links)

A report link delivers `<variable>.value` = list of `{value, unit, timestamp}` (timestamp = Excel date). The templates
read the first sample (`value[0]`) or iterate the list (`jx:each`, parallel lists by `varIndex`). Variable =
`<stem>_Value_MONTHLY_<period>`, period `CURRENT` (report period), `LAST` (previous period),
`FIXED_TO_REPORT_END` with fixed period `YEAR` (12 months up to the report end); aggregation `MONTHLY`.

| Report | Stems and periods |
|---|---|
| EnPI | `EnPI_{Strom,Gas}_{Gesamt,Verwaltung,Produktion}` CURRENT, LAST, FIXED_TO_REPORT_END; `Strom_{Gesamt,Verwaltung,Produktion}`, `Gas_main_meter_energy`, `Gas_{Verwaltung,Produktion}`, `Produktionsmenge` CURRENT, LAST; **new:** `Strom_Produktion`, `Produktionsmenge` FIXED_TO_REPORT_END (baseline) |
| Energy management | `Strom_{Gesamt,Verwaltung,Produktion,HLK,Drittmengen}`, `Gas_Hauptzaehler_Energie`, `EnPI_{Strom,Gas}_Gesamt` CURRENT; `Strom_Gesamt`, `Gas_Hauptzaehler_Energie`, `EnPI_{Strom,Gas}_Gesamt` LAST (before: FIXED/YEAR); **new:** `Kosten_{Strom,Gas}_Netto` CURRENT and LAST (series `NET` of the energy invoices); energy management link `enms` |

Missing data: JEReport puts `NO DATA` into a sample; sums and means ignore it, changes stay empty.

## Energy management link (new class)

Class **`Energy Management Link`** (`var/classes/ReportPlugin`, translations in `var/i18n/ReportPlugin`), child of a
report link directory like `Alarm Link`; attributes `Target` (organisation or building) and `Template Name`
(variable, e.g. `enms`). JEReport (`EnergyManagementFunction`) reads the action plans (`Action Plan v2`) and
nonconformity plans below the target with the same models as the web app (`ActionItem`, `NonconformityItem`) and
puts for the report period [start, end):

- `periodStart`, `periodEnd` (`dd.MM.yyyy`, end = last day);
- `actions` (all not deleted, created before the end), `actionsOpen` (not done by the end), `actionsDoneInPeriod`;
  each row = the web API fields of an action plus `plan`, `createDateText`, `plannedDateText`, `doneDateText`,
  `done`, `doneInPeriod`, `savingKWh` (consumption diff), `savingEuroPerYear` (NPV saving), `investment`;
- `actionSummary`: `total`, `open`, `done`, `doneInPeriod`, `plannedSavingKWh` (open), `achievedSavingKWh` (done),
  `savingEuroPerYear` (done), `investment` (all);
- `nonconformities`, `nonconformitiesOpen`, `nonconformitiesClosedInPeriod`; rows = web API fields plus `plan`,
  date texts, `open`, `overdue` (planned date before the end, not closed);
- `nonconformitySummary`: `total`, `open`, `overdue`, `newInPeriod`, `closedInPeriod`.

The link never blocks a report (no data dependency); without a readable target it reports a failed sanity check.

## Formulas

`TemplateTransformator` evaluates every formula after filling (the PDF via LibreOffice and viewers without
recalculation show values). A function POI cannot evaluate is left to Excel/LibreOffice and logged instead of failing
the report (therefore R² = `CORREL(...)^2`, POI has no `RSQ`/`LINEST`).

## Setting up the demo (live)

After the deployment (web service restart for the new class, JEReport rebuilt and restarted), one-time and only after
confirmation of a dry-run report, with the user's own login (Control Center harness, as for the alarm flags):

1. `EnPI-Bericht - Werk`: upload `EnPI-Bericht.xlsx` as `Template`; add the two FIXED_TO_REPORT_END links for the
   baseline.
2. `Energiemanagement Bericht`: upload `Energiemanagementbericht.xlsx`; schedule `YEARLY`, start record = start of the
   previous year; the four `…_FIXED` links become `…_LAST` (period `LAST`, variable renamed); add the four cost links
   (invoice series `NET` per medium) and the energy management link (`enms`, target = demo organisation).
3. JEReport creates the reports in its next cycle; check them in the web app (*Berichte*).
